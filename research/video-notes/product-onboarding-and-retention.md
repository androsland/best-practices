# Product onboarding and retention

S13 argues that acquisition is not success when new users fail to reach value and disappear (`S13 00:00–00:38`). Its three-part framework is a useful starting point.

## 1. Optimize time to first value

Define the smallest action that proves the product’s core benefit, then help a new user complete it quickly.

- Measure from account creation to the first meaningful outcome, not merely to onboarding completion.
- Use templates, sample data, imports, or smart defaults when they shorten the path without misleading the user.
- Let the user perform the core action instead of making them watch a tour or read documentation.
- Treat “within 60 seconds” as an ambitious hypothesis from S13 (`00:38–01:08`), not a universal benchmark.

Example: a project-management product can create a real project with an actionable first task during onboarding.

## 2. Reveal complexity progressively

- Start with the core workflow.
- Introduce customization after the user has completed the first outcome.
- Present integrations and advanced controls when there is evidence the user needs them.
- Keep features discoverable; progressive disclosure should reduce cognitive load, not hide capability.

The reel suggests milestone-based reveal across successive sessions (`S13 01:10–01:37`). Validate this through usability testing rather than hard-coding an arbitrary session count.

## 3. Re-engage with created value

Prefer an event tied to the user’s work over a generic “come back” message (`S13 01:37–02:04`).

Useful triggers include:

- a task the user created is due;
- an imported process finished;
- a collaborator responded;
- a report is ready;
- a saved item changed materially.

Respect consent, notification preferences, time zones, quiet hours, and data-minimization requirements. Do not place sensitive user data in notification previews or email subject lines.

## Measurement plan

Track a funnel based on product value:

1. Signup completed.
2. First meaningful action started.
3. First value reached.
4. Second independent use session.
5. Day-7 and day-30 retained use, segmented by acquisition source and onboarding path.

Pair conversion data with interviews and session-level usability evidence. A retention drop does not by itself prove onboarding is the sole cause; product fit, reliability, performance, price, expectations, and acquisition quality may also matter.

## Implementation checklist

- Name the first-value event precisely.
- Establish a baseline distribution, not only an average.
- Remove steps that do not help users reach the event.
- Add defaults or templates and test their effect.
- Gate advanced complexity based on behavior or explicit user choice.
- Create relevant, consented re-engagement triggers.
- Run controlled experiments and monitor unintended effects.
